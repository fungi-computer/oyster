---
title: Agent quick start
description:
  Run Oyster locally with one command, open Hello, then edit and restart.
  Connect MCP, build another App or deploy when you are ready.
---

You are an agent setting up Oyster for a person. Start with a local desktop and
one working App. You need **Node 24 or newer and Git**, an internet connection
for the first install, and a browser to see the result. No Cloudflare account,
Docker or payment is needed for this trial.

## 1. Start Oyster

In the directory where the person wants to keep their project, check the tools:

```sh
node --version
git --version
```

Expect Node `v24` or newer and a Git version. If either is missing or Node is
older, install it before continuing.

Keep the next command running in a persistent terminal or your agent runtime's
managed process session:

```sh
npx --yes @fungi.computer/oyster try --no-open
```

It creates `./my-oyster`, installs dependencies, starts Oyster on
`http://127.0.0.1:8787`, installs Hello and builds Tourtois, the desktop, from
its public source. `--no-open` lets you open the sign-in link yourself; omit it
on a person's computer to open their browser automatically.

On a fresh install, expect these phases, with timing and progress alongside:

```text
Creating my-oyster
Installing dependencies with npm
Starting Oyster
Installing Hello and building Tourtois
Preparing desktop sign-in
Oyster is running
```

Then Oyster prints `Open (works once):` with a local sign-in URL, the Oyster
address, and paths to the owner key and Hello source. The key is saved in
`my-oyster/.oyster-owner`; it is never printed or put in the sign-in URL. Treat
the one-time URL and the key as credentials: do not put them in reports.

Keep this terminal running while you use the desktop. If there is no success or
failure after five minutes, inspect the logs under `my-oyster/.oyster/` and
report the last phase; do not silently leave a stalled process running.

If it fails:

- **Port in use:** leave that listener alone. Follow the suggested command with
  another port, such as `--port 8788`, and use the address Oyster prints.
- **Directory already has files:** choose a new directory with
  `npx --yes @fungi.computer/oyster try another-oyster --no-open`. Do not delete
  someone else's project.
- **Install or startup error:** read the diagnostic and the log path it names.
  Keep the project, fix the reported cause and rerun the same command. Oyster
  preserves your key and source; `--verbose` shows install and server logs.
- **Oyster needs desktop repair:** the host is available for recovery, but the
  desktop is not ready. Follow the printed repair diagnostic and report it; this
  is not a successful trial.

## 2. Open Hello

Open the printed one-time link in a browser on the same machine as Oyster. From
the Tourtois launcher, choose **Hello**. Success means the App visibly reads
**Hello from my first Oyster App**, without a loading or timeout overlay. An
HTTP 200 alone does not prove that the desktop or App opened.

If the link has expired or was already used, open the printed Oyster address
with `/login` appended and paste the key from `my-oyster/.oyster-owner` into the
login form. If your agent cannot use a browser on that machine, give the person
these steps and report that the visible check is still unverified.

The local trial has no Computer, hosted git storage or Workers AI. Opening Hello
does not prove a cloud deployment or a model reply.

## 3. Stop, restart and edit

Press Ctrl-C in the terminal that owns this trial to stop it. In an agent
runtime, stop your managed session and its children; do not kill processes by a
shared name or port. From the **same parent directory** as step 1, restart:

```sh
npx --yes @fungi.computer/oyster try my-oyster --no-open
```

Or, from **inside `my-oyster`**, run:

```sh
npx --yes @fungi.computer/oyster try . --no-open
```

Use the directory and `--port` you chose if they differ. Expect
`Restarting the Oyster in …`, then `Installing Hello and checking Tourtois`,
followed by a new sign-in link. Your owner key and Hello source stay in place.

To make the first edit, change the heading in
`my-oyster/hello-app/bundle/index.html`. Keep the `main.js` script: it tells
Oyster that the App is ready. Save it, then from the **parent directory** commit
the change in the `hello-app` Git repository:

```sh
git -C my-oyster/hello-app add bundle/index.html
git -C my-oyster/hello-app -c user.name="Oyster learner" \
  -c user.email="oyster@example.invalid" commit -m "Edit Hello"
```

Expect a commit summary with one changed file. This example supplies an identity
for just this commit, so it also works on a machine without global Git settings.
Use your own name and email if you prefer. Adjust `my-oyster` if you chose
another project directory.

Stop and restart Oyster as above. It builds committed source; saving or
refreshing alone does not install an edit. Open the new sign-in link and choose
Hello again to check the changed heading.

The [build-an-App recipe](https://docs.fungi.computer/agents/build-an-app.md)
has exact edit commands and the next App to build.

## After the local trial

Stop here unless the person wants the next step. These are separate tasks:

- **Connect MCP:** use the
  [MCP guide](https://docs.fungi.computer/oyster/concepts/#connect-an-agent-over-mcp)
  for the `/mcp` endpoint and authentication. For this trial, use the printed
  local Oyster address and the owner key in `my-oyster/.oyster-owner`. Hello is
  a static page; connecting MCP does not give it backend methods.
- **Build another App:** follow the
  [build-an-App recipe](https://docs.fungi.computer/agents/build-an-app.md),
  then the [App guide](https://docs.fungi.computer/apps/) for backends and typed
  methods.
- **Deploy:** follow
  [Run your own Oyster](https://docs.fungi.computer/guides/run-your-own-oyster/#deploy-it).
  That step needs your own Cloudflare account, paid resources and Docker for the
  Computer image. Do it only when the person asks for hosting.

For manual setup, the ordinary
[quickstart](https://docs.fungi.computer/oyster/quickstart/) keeps the Wrangler
commands under **What it does under the hood**. The
[Oyster concepts](https://docs.fungi.computer/oyster/concepts/) and
[API reference](https://docs.fungi.computer/oyster/api/) cover custom hosts,
packing Releases and Git integration.
